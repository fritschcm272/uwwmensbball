🎥 HOW THE FILM IS WATCHED AUTOMATICALLY

How it works

  1. Capture. For every tagged clip, the parser opens the game on Synergy and saves still frames of the play: 5 key frames, plus 4 frames a second for player tracking.
  2. Players. A detection model finds every person in each frame; a one-time court calibration per gym places them on the floor; jersey colors split the teams, and referees, coaches and fans are set aside. Each player is followed frame to frame and across back-to-back plays. Names come from the coaches' checks, a jersey-number reader trained on our own film, and the five known to be on the floor (play-by-play substitutions); anyone else gets a best guess, marked as one.
  3. Plays. The Tag model learns the coaches' Titles from Synergy's description of each play, its key frames and the players' positions, then writes an automatic Title -- formation, play call, situation, defense, press, coverages -- for every play, tagged or not.
  4. Coaches' reviews. Each run builds a review of 20 random plays per game. A coach checks the players and the automatic Title; every check becomes a certain name and training data, so the models improve with each review.

So far: 8 game(s) captured (1,024 clips); 9 game(s) tagged by the coaches (1,081 plays); 8 game(s) tracked (1,009 plays, 84,729 frames). Coach reviews: 697 player check(s) on 99 play(s), 327 Title answer(s) on 88 play(s); 20 tagged plays held out of training to test the Tag model. Players on the floor named from evidence (not a best guess): 700 of 6,150.

How to read these counts

  • Only boxes and answers a coach actually judged count. A box left on -- not checked -- is never saved, so it is never counted as right or wrong.
  • A name is not right when the coach marked it really someone else (right team, wrong player), wrong team, or not a player; each Right-name row lists which.
  • Named by ... is how the film had named that box when its review page was built, so it reflects that run's naming, even if a later run names the player differently.
  • A box checked in more than one saved review counts once -- the latest check.
  • Small samples move a lot from one run to the next -- a row with only a few checks says little yet. Read these as where things stand today, not final grades.

How the coaches' review answers are used

  • right = the automatic answer was correct; wrong + a typed answer = the typed answer is correct; wrong with nothing typed, or can't tell = only the mark is kept (no answer to learn).
  • The latest saved answer for a play's field counts -- an older one is replaced, never added.
  • Every answer becomes what the Tag model learns for that play: it fills fields the coach's Title left empty and, when it disagrees with the coach's Title, it overrides it. The model retrains on the next run.
  • Rows prefilled as wrong (the coach's value differed from the automatic one) and left untouched never override anything and are not counted as reviews -- the coach-Title comparison already counts them. Changed or re-picked, they count.
  • The Coach values and the coach-Title comparisons above always show what the coach actually tagged; only what the model learns changes. Validation plays are never trained on, answers included.
  • A typed answer that matches a known answer apart from capitals, spaces or punctuation is stored in the known spelling ('2-3 zone' -> '2-3 Zone'); a genuinely new answer is kept as typed and listed in the parser's output to check for typos.
  • Review answers never change uww_plays.csv; the brief and app still report the coach's Titles.
  • The most recent review beats a coach's later re-tag of the same play -- to let a new tag stand, change or clear that play's answer in a review.
